## Detailed Risk Register

### TECH-001 – Filesystem Discovery Fragility
- **Category:** Technical
- **Description:** `ComfyUIOutputAdapter` relies on heuristics and optional `folder_paths` import; uncommon install layouts or permission constraints can surface IOErrors or incomplete scans. [Source: docs/architecture/technical-debt-and-known-issues.md#workarounds-and-gotchas]
- **Affected Components:** `src/adapters/driven/comfyui_output_adapter.py`, `src/adapters/driven/filesystem_output_adapter.py`, `OutputService` caching layer.
- **Detection Method:** Static analysis of adapter heuristics + existing TODOs; reproduce via sandboxed directories lacking expected indicators.
- **Probability:** Medium (2) – non-standard setups appear regularly in community installations.
- **Impact:** High (3) – gallery payloads empty or error, blocking Outputs tab functionality.
- **Score:** 6 (High)
- **Mitigation Plan:**
  - Harden adapter path detection with explicit configuration override support and unit tests covering macOS/Linux/Windows roots.
  - Ensure IOErrors funnel through service-level validation to deliver structured error payloads and logs rather than uncaught exceptions.
  - Document environment overrides in developer guide.
- **Residual Risk After Mitigation:** Low – if tests cover path permutations and errors map to user-facing messaging.

### PERF-001 – Scan Throughput & Cache Thrash
- **Category:** Performance
- **Description:** Large output directories (hundreds/thousands of images) plus cache invalidation may cause long-running scans, blocking event loop and triggering 500s under load. [Source: docs/architecture/technical-debt-and-known-issues.md#critical-technical-debt]
- **Affected Components:** `OutputService.get_all_outputs`, cache TTL handling, thumbnail generation.
- **Detection Method:** Review OutputService algorithm + prior performance TODOs; simulate with seeded directories and async profiling.
- **Probability:** High (3) – typical ComfyUI users accumulate large galleries.
- **Impact:** Medium (2) – degraded responsiveness, possible timeouts.
- **Score:** 6 (High)
- **Mitigation Plan:**
  - Add batching or generator-based scanning with early pagination support; ensure cache prevents redundant thumbnails.
  - Include performance-focused pytest/benchmark coverage referencing spec task #7.
  - Surface progress logs/timers for slow scans to aid monitoring.
- **Residual Risk After Mitigation:** Medium – dependent on production gallery sizes; consider feature flag for experimental pagination.

### TECH-002 – Cross-Platform Workflow Actions
- **Category:** Technical
- **Description:** `open-system` / `show-folder` rely on platform shell commands; edge cases (headless Linux, permission errors) may yield failure without clear messaging. [Source: docs/architecture/appendix-useful-commands-and-scripts.md#debugging-and-troubleshooting]
- **Affected Components:** `FilesystemOutputAdapter.open_file_in_system`, `show_file_in_folder`, WebAPIAdapter workflow endpoints.
- **Detection Method:** Manual invocation on varied OS targets and negative-path unit tests mocking subprocess failures.
- **Probability:** Medium (2)
- **Impact:** Medium (2) – workflow utilities fail, eroding user trust though gallery still functions.
- **Score:** 4 (Medium)
- **Mitigation Plan:**
  - Standardise subprocess handling with explicit exit-code checks and map failures to actionable JSON responses.
  - Extend unit/integration tests with OS-specific mocks.
  - Document copy-path fallback behaviour for headless contexts.
- **Residual Risk After Mitigation:** Low – assuming robust mocks and documentation.

### OPS-001 – Logging Gaps Obscure Failures
- **Category:** Operational
- **Description:** Existing logging guidance emphasises reuse of `src/utils/logger.py`, yet gaps around enrichment failures or workflow actions may persist, complicating incident triage. [Source: docs/architecture/appendix-useful-commands-and-scripts.md#debugging-and-troubleshooting]
- **Affected Components:** `OutputService` enrichment paths, WebAPIAdapter error branches.
- **Detection Method:** Code review and log sampling; identify branches lacking structured log messages.
- **Probability:** Medium (2)
- **Impact:** Medium (2) – increases MTTR when diagnosing production errors.
- **Score:** 4 (Medium)
- **Mitigation Plan:**
  - Define minimum logging fields (action, output_id, OS, exception) and add tests asserting log emission where feasible.
  - Update developer docs with logging expectations.
- **Residual Risk After Mitigation:** Low – provided logging checklist enforced.

### BUS-001 – Contract Drift With Existing Clients
- **Category:** Business
- **Description:** Frontend and test suites rely on current `/asset_manager/outputs` payload schema; backend adjustments risk removing keys or changing error envelope, breaking consumers. [Source: docs/prd/epic-1-outputs-first-release.md#story-11-outputs-backend-hardening]
- **Affected Components:** WebAPIAdapter response builders, `ui/src/services/api.ts`, Vitest/Playwright specs.
- **Detection Method:** Regression testing via existing API contract tests and Playwright suites.
- **Probability:** Low (1)
- **Impact:** High (3) – Live UI regressions and failed automation runs.
- **Score:** 3 (Low)
- **Mitigation Plan:**
  - Introduce contract tests asserting response shape and required properties.
  - Coordinate with frontend maintainers before altering DTO fields.
  - Maintain API changelog entry if schema adjustments unavoidable.
- **Residual Risk After Mitigation:** Minimal – assuming contract tests enforced in CI.

## Risk-Based Testing Strategy

### Priority 1 – High Risks (TECH-001, PERF-001)
- Develop pytest scenarios covering nonexistent/permission-denied directories and malformed metadata to confirm graceful error payloads.
- Load-test output scans with large fixture directories; measure latency to ensure watchdog thresholds respected.
- Add asynchronous integration test ensuring cache invalidation doesn’t trigger redundant filesystem walks.

### Priority 2 – Medium Risks (TECH-002, OPS-001)
- Mock subprocess failures per OS to validate workflow action responses and log records.
- Verify log outputs (via caplog) include action context and correlation data.
- Extend Playwright smoke test to exercise copy-path fallback when ComfyUI globals absent.

### Priority 3 – Low Risk (BUS-001)
- Run existing Vitest and Playwright suites to confirm response schema stability.
- Add snapshot/contract tests for `/asset_manager/outputs` JSON payloads.

## Development & Review Focus
- Prioritise code review on adapter path detection, cache invalidation logic, and DTO construction.
- Require reviewers to verify structured logging and error envelopes align with existing conventions.

## Deployment & Monitoring Recommendations
- Perform staged rollout with feature flag to monitor scan latency and error rates before wide release.
- Configure monitoring on:
  - `/asset_manager/outputs` request latency and 5xx counts.
  - Workflow action failure rates by platform.
  - Count of “graceful fallback” events during enrichment.

## Risk Acceptance Criteria
- **Must Mitigate Pre-Release:** TECH-001, PERF-001 (score ≥ 6).
- **Mitigate or Document:** TECH-002, OPS-001 via tests/logging improvements.
- **Monitor:** BUS-001 via regression suites and release notes.
- **Accepted Risks:** None at this time; revisit if mitigation infeasible.
