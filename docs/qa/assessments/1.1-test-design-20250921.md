# Test Design: Story 1.1 Outputs Backend Hardening

Date: 2025-09-21
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 15
- Unit tests: 5 (33%)
- Integration tests: 9 (60%)
- E2E tests: 1 (7%)
- Priority distribution: P0: 4, P1: 11, P2: 0, P3: 0

## Test Scenarios by Acceptance Criteria

### AC1: API responses handle empty directories, malformed metadata, expected gallery sizes; logging covers failure modes.

#### Scenarios

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.1-UNIT-001 | Unit | P0 | Validate `OutputService._enrich_output` returns original entity when metadata/thumbnail extraction fails. | Critical logic isolation preventing 500s; mitigates TECH-001. |
| 1.1-UNIT-002 | Unit | P1 | Verify cache invalidation in `OutputService.refresh_outputs` refreshes stale entries and respects TTL. | Keeps scan throughput manageable; mitigates PERF-001. |
| 1.1-INT-001 | Integration | P0 | GET `/asset_manager/outputs` on empty directory returns 200, empty list, and emits structured log. | Core API contract for empty installs; mitigates TECH-001. |
| 1.1-INT-002 | Integration | P0 | GET `/asset_manager/outputs` with malformed PNG metadata still returns enriched payload sans workflow and records warning log. | Guards against malformed inputs; mitigates TECH-001. |
| 1.1-INT-003 | Integration | P0 | GET `/asset_manager/outputs` against large gallery fixture stays under agreed latency threshold and avoids cache thrash. | Performance risk coverage; mitigates PERF-001. |
| 1.1-INT-004 | Integration | P1 | GET `/asset_manager/outputs` with invalid query params (date/format) returns 400 validation error envelope. | Ensures actionable feedback and prevents 500s. |
| 1.1-INT-005 | Integration | P1 | POST `/asset_manager/outputs/refresh` rescans directory, returns updated list, and preserves DTO schema. | Confirms refresh path matches contract and logging. |

### AC2: Workflow actions return actionable success/failure payloads across OS cases.

#### Scenarios

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.1-UNIT-003 | Unit | P1 | Mock `subprocess.run` in `open_file_in_system` to cover success and failure paths per OS branch. | Pure logic; ensures deterministic responses; mitigates TECH-002. |
| 1.1-UNIT-004 | Unit | P1 | Validate `show_file_in_folder` selects correct OS command and handles missing files gracefully. | Prevents platform drift; mitigates TECH-002. |
| 1.1-INT-006 | Integration | P1 | POST `/asset_manager/outputs/{id}/open-system` success path returns `success=True` with message. | Verifies API envelope consumed by UI; mitigates TECH-002. |
| 1.1-INT-007 | Integration | P1 | POST `/asset_manager/outputs/{id}/open-system` when subprocess fails returns 500 with `system_operation_failed` payload and log entry. | Ensures actionable failure messaging; mitigates TECH-002 & OPS-001. |
| 1.1-INT-008 | Integration | P1 | POST `/asset_manager/outputs/{id}/load-workflow` with missing workflow metadata returns 404 `workflow_not_found`. | Confirms failure response and logging; aligns with AC2. |

### AC3: Standard logging provides actionable summaries for workflow outcomes without new telemetry.

#### Scenarios

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 1.1-UNIT-005 | Unit | P1 | Use `caplog` to ensure enrichment failure paths log action, output id, and exception via `logger`. | Validates logging contract at lowest level; mitigates OPS-001. |
| 1.1-INT-009 | Integration | P1 | Trigger workflow action failure and assert structured log includes action, platform, correlation id. | Verifies end-to-end logging expectations; mitigates OPS-001. |
| 1.1-E2E-001 | E2E | P1 | Playwright run: simulate Outputs tab with backend returning error payloads to ensure UI shows fallback message without 500. | Confirms user-facing behavior and no telemetry regression; catches contract drift BUS-001. |

## Recommended Execution Order

1. P0 unit/integration tests: 1.1-UNIT-001, 1.1-INT-001, 1.1-INT-002, 1.1-INT-003
2. Remaining unit tests (P1): 1.1-UNIT-002, 1.1-UNIT-003, 1.1-UNIT-004, 1.1-UNIT-005
3. Integration tests (P1): 1.1-INT-004 through 1.1-INT-009 (in numeric order)
4. E2E scenario: 1.1-E2E-001 once backend coverage is green
